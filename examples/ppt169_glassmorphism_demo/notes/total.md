# 01_cover

大家好，歡迎來到這次技術分享。今天的主題是 AI Agent 工程化與落地——也就是說，我們不聊新模型，不聊新論文，專門聊一件事：怎麼把那些跑得動 Demo 的 Agent，真正搬進生產環境裡。

---

# 02_hero_demo_to_prod

先拋一個讓人有點不舒服的事實。在我和很多團隊的交流裡，大約九成的 Agent 專案最後都停在了 Demo 階段。原因不是模型不夠強，也不是想法不夠好，而是要進生產，需要跨過四道工程化門檻——架構、上下文、評估、可觀測。這四件事一件沒做，Demo 就永遠只能是 Demo。

---

# 03_three_pains

第一道是效能不穩定，多步推理一疊加，每一步五到十個百分點的抖動累計起來，整體成功率就會斷崖式下滑，P95 延遲更是常常翻五到十倍。第二道是成本不可預測，同一個任務在不同上下文長度下，單次 token 消耗能漂移五到五十倍，長尾任務尤其會吞掉預算。第三道是質量難閉環，失敗原因是模型問題、提示詞問題、還是資料問題往往說不清楚，迴歸測試也沒有，一改 prompt 就提心吊膽。這三道門檻，是絕大多數專案都會先撞上的。

---

# 04_agent_architecture

接下來我們看一下 Agent 的標準骨架。基本上可以分成四層。最上面是感知層，負責輸入解析、多模態融合、上下文視窗管理。第二層是推理層，承擔 Plan、ReAct、Tree-of-Thought、Reflection 這些決策正規化。第三層是行動層，把模型的決策落到工具呼叫、函式執行、API 編排上。最下面是記憶層，包括短期上下文、長期向量庫和任務級快取。每一層都有自己的工程化坑，但只要框架對了，每一層都能獨立打磨和替換。

---

# 05_three_modes

理解了四層骨架之後，下一個常見問題是：到底用哪種模式。簡單說有三種。Workflow 是路徑固定的 DAG，LLM 只負責填空，可預測、好除錯，適合確定性任務。Agent 是路徑動態的，執行時讓模型自己決定下一步，最常用、也是大部分專案真正在做的事，適合半結構化的探索類任務。Multi-Agent 是多角色協作，把 Planner、Critic、Worker 拆開併發協作，靈活性最高，但複雜度也最高，只在真正需要長程任務的時候用。絕大多數生產場景，從 Agent 開始就夠了。

---

# 06_tool_orchestration

把模式確定下來之後，最先開始做的就是工具編排。一個穩定的工具呼叫大致是六步：先解析任務、再選工具、然後呼叫執行、接著驗證返回、必要時重試或回退、最後做結果彙總。每一步都要可觀測，每一步都要有兜底。最常見的翻車點不在第一步而在第四步——大家往往拿到工具返回就直接餵給模型，缺了 schema 驗證和業務規則校驗，幻覺就是從這裡漏進來的。

---

# 07_context_engineering

講完工具，下面這頁是我個人覺得最重要的一頁：上下文工程。模型每天都在變，提示詞也每天都在調，但真正決定一個 Agent 智不智慧的，是它每一步看到了什麼——也就是上下文。圍繞這一個核心，至少要做好六件事：檢索要穩，重排要準，截斷要會取捨，記憶要分長短期，工具說明要夠具體，系統提示要把人設、輸出格式、安全規則都講清楚。上下文工程做不好，模型再強也救不回來。

---

# 08_kpi_dashboard

接下來切到運營視角。要上生產，你必須給自己裝上四塊錶盤。第一塊是任務成功率，目前這套系統跑到了百分之九十二點四，還在每週提升三個百分點。第二塊是 P95 延遲，從初版的十一秒多，收斂到了四點八秒。第三塊是單次任務成本，做了模型分級路由和檢索結果快取之後，單次成本壓到了四毛二。第四塊是三十天 SLO 達成率，靠多模型 fallback 兜住了上游事故，目前在百分之九十九點七。這四個數沒有，就別談上生產。

---

# 09_metrics_trend

把這四個指標拉成時間軸，就能看到一條很真實的曲線。綠色是任務成功率，從最早的百分之七十一，一路爬到了百分之九十二點四。紅色是單次成本，從一塊二降到了四毛二。最關鍵的三個拐點都標在圖上：第四周引入了 reranker，準確率跳了一檔；第八週引入了 fallback，長尾任務的成本和失敗率一起被壓下來；第十一週引入了結果快取，成本下了最大的一刀。每一次提升的背後，都對應一個具體的工程動作，不是靠運氣，也不是靠換模型。

---

# 10_failure_modes

聊一聊會遇到的失敗。大致可以分到四個象限。左上是高頻淺層的工具錯誤，schema 不匹配、引數幻覺、超時無回退，這一類靠提前校驗就能擋住。左下是低頻但麻煩的死迴圈，反思鏈路沒有終止條件，Plan 反反覆覆改，必須設硬性停機條件。右下是更難處理的幻覺，編造工具、編造結果，甚至假裝成功，這一類只能靠 Grounding，讓每一步都對接真實資料來源。右上是隱蔽的成本失控，Token 漂移、重複檢索、鏈路套娃，必須做計量和上限。預案的關鍵，是分類別準備，不是事後撲火。

---

# 11_roadmap

把這些東西整合起來，給一個十二週可執行的落地路線。第一階段是前三週，跑通最小可用的原型，金標準 case 透過率到八成以上，再進下一階段。第二階段是第四到第七週，把評估集鋪到一百條以上，自動迴歸點亮綠燈，重試和降級機制全部上。第三階段是第八到第十週，規模化，加快取、加限流、做多租戶隔離、做模型分級路由。第四階段是第十一到第十二週，灰度上線，從百分之一到百分之十再到全量，盯住 SLO，讓飛輪真正轉起來。每個階段都要有"通關"硬指標，否則就只是在趕進度。

---

# 12_cta_closing

最後總結一句話。所謂的 Agent 工程化，不是給系統里加一個 LLM 就完事了，而是把 LLM 真正裝進一個有架構、有上下文、有評估、有可觀測的工程系統裡。這四件事一起做，Agent 才能從 Demo 走到生產。希望今天分享的這套框架，能幫到正在路上的你。謝謝大家。
