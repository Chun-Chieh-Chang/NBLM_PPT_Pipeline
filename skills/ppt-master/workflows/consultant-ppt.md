# Consultant PPT Workflow (CyberPPT Integration)

將源材料轉化為有證據鏈、結論先行、可編輯的諮詢式演示文稿。使用 MBB 級標準審視證據、論證和頁面架構。

## 適用場景

- 諮詢風格 PPT，高信息密度
- 行業研究、消費者分析、品牌戰略、電商分析
- 用戶研究、高管匯報、董事會材料、客戶提案
- 項目復盤、戰略決策報告

## 不適用場景

- 字數少的低信息密度風格
- 演講、個人風格表達、敘事、分享、觀點類 PPT

## 強制流程

| 階段 | 必須產出 | 停止條件 | 讀取 |
|------|----------|----------|------|
| 1. 分析 | MBB 標準證據表、衝突記錄、內容腦暴子步驟、SCR 論證、逐頁大綱、圖表計劃、頁面信息密度和組件清單 | 第一次確認：用戶批准故事線、頁數、大綱、每頁信息結構和密度目標 | `references/cyberppt/source-analysis.md`, `references/cyberppt/storyline.md` |
| 2. 藍圖 | 8 種視覺風格、選定風格、覆蓋全部請求/計劃頁數的逐頁 ImageGen 藍圖 | 第二次確認：用戶批准視覺方向和全部頁面藍圖 | `references/cyberppt/visual-system.md` |
| 3. 混合還原 PPTX | 採用「複雜視覺保真 + 主要文字可編輯」的混合還原策略，輸出 PPTX、全頁渲染圖、對照檢查和可編輯性說明 | 最終確認：用戶批准可編輯 PPT | `references/cyberppt/ppt-production.md`, `references/cyberppt/quality-assurance.md` |

**未經確認不要跨過確認門。用戶要求修改時，回到對應階段修訂並重新確認。**

## Reference Gate

每個階段開始前必須讀取上表「讀取」列中的全部 reference 文件，並把該階段關鍵約束轉成執行清單後再行動。

### 階段 1 Reference Gate
必須讀取：
- `references/cyberppt/source-analysis.md` — MBB 證據表格式、衝突處理、缺失信息管理
- `references/cyberppt/storyline.md` — SCR 論證結構、逐頁計劃格式、結論標題測試

### 階段 2 Reference Gate
必須讀取：
- `references/cyberppt/visual-system.md` — 8 種固定風格、色板、網格、字級、密度規則

### 階段 3 Reference Gate
必須讀取：
- `references/cyberppt/ppt-production.md` — 混合還原策略、雙硬門檻、還原規則
- `references/cyberppt/quality-assurance.md` — 靜態/動態 QA、14 層門禁

## 階段 1：證據分析 + 內容腦暴 + SCR + 頁面密度規劃

### 硬性要求

1. 所有事實、數字、判斷、建議、caveat 和 SO WHAT 都必須能追溯到源材料位置或明確標記為缺口。
2. 必須建立 MBB 標準證據表，記錄來源位置、期間、單位、置信度、衝突、caveat、含義和推薦視覺。
3. 必須完成內容腦暴子步驟：提出 2-3 條可選故事線，建立 issue tree 或 hypothesis tree，並比較證據強度、風險缺口、適用受眾和不推薦原因。
4. 必須形成頁面物料池：關鍵數字、對比、排名、變化、漏斗、矩陣、表格、註釋、圖例、微圖表、邊欄洞察和可用證據 ID。
5. 必須輸出推薦故事線，而不是只給一個看似合理的大綱。
6. 必須為每頁定義信息密度和組件清單。
7. 不得讓用戶只確認頁標題；第一次確認必須覆蓋故事線、頁數、逐頁論點、圖表計劃、信息密度和組件清單。

### 工作順序

1. 盤點輸入文件和材料角色
2. 抽取事實、數字、表格、圖形、論點、日期、單位和來源
3. 建立證據表，並標記衝突、缺口和僅方向性判斷
4. 基於證據表做內容腦暴，提出 2-3 條可選故事線
5. 比較故事線，選擇推薦路徑並說明取捨
6. 將推薦路徑收斂為全篇 SCR
7. 生成逐頁計劃：結論標題、角色、詳細論證、證據、caveat、圖表計劃、視覺、含義、承接
8. 為每頁補齊頁面信息密度和組件清單，作為第二階段藍圖輸入

### 第一次確認輸出

- MBB 證據表摘要
- 開放數據衝突、缺失證據和 caveat
- 2-3 條可選故事線與推薦理由
- 推薦 SCR
- 逐頁大綱和圖表計劃
- 逐頁頁面信息密度和組件清單
- 需要用戶決策或補充的數據問題

### 禁止事項

- 不得跳過內容腦暴，直接提交單版大綱
- 不得使用常識補源材料沒有的數據
- 不得把 ImageGen 文字、數字、Logo、引文或圖表值當作證據
- 不得輸出只有「頁面標題 + 簡短描述」的低密度大綱
- 不得把低密度風險留給藍圖階段自行解決

## 階段 2：8 張固定樣張 + 逐頁 ImageGen 藍圖

### 硬性要求

1. 必須直接通過當前對話發送 8 張獨立完整的 16:9 樣片圖片供用戶選擇。
2. 樣片路徑：`templates/palette-samples/palette-01.png` 到 `palette-08.png`
3. 網頁、HTML、URL、文件列表、Markdown 表格、文字說明、拼圖或縮略圖牆只能作為補充，不能替代當前對話中的 8 張獨立樣片圖片。
4. 在用戶能夠在当前對話中直接看到 8 張樣片之前，不得請求用戶選擇風格，不得進入逐頁藍圖階段。
5. 不得只生成 Markdown、表格、文本列表或推荐理由作為風格確認物。
6. 預設必須使用固定 8 種 CyberPPT 視覺風格；除非用戶明確要求替換，否則不得改成臨場擴展風格。
7. 選定風格後，必須聲明並鎖定風格編號、名稱、色板、網格、標題層級、圖表語言、頁眉頁腳和信息密度規則。
8. 逐頁藍圖必須使用第一步確認的頁面信息密度和組件清單，不得把高密度計劃降級成寬鬆卡片、泛化圖表或稀疏大字報。
9. 藍圖中的文字和數字只作為構圖佔位，最終 PPT 文本、數據、表格值、圖表值和來源必須從證據表重建。

| 03 | 暖象牙白 + 暗酒紅 | `#F4F1EA` | `#8A1538` | 品牌戰略、消費品、電商 |
| 04 | 象牙白 + 深藍強調 | `#F7F6F0` | `#12355B` | 科技、SaaS、B2B、企業數字化 |
| 05 | 淺灰白 + 墨綠 | `#F2F3EF` | `#1F5B4D` | 可持續、海外市場、增長戰略 |
| 06 | 紙張米色 + 銅棕 | `#F4F0E8` | `#9A5A2E` | 消費、零售、奢侈品、商業模式 |

### 第二次確認輸出

- 8 張獨立 16:9 風格樣片圖片
- 風格編號、名稱、色板、適用語氣、優勢和風險
- 用戶選定後的視覺系統鎖定說明
- 覆蓋全部頁數的逐頁 ImageGen 藍圖
- 每頁藍圖的組件清單、可編輯文本區域、複雜視覺資產區域、證據 ID 和密度目標
- 需要用戶確認的風格漂移或信息密度風險

## 階段 3：複雜視覺保真 + 主要文字可編輯

### 混合還原策略

最大優先級是保留原圖的整體設計質感、構圖、視覺完成度和高級感，同時保證主要文字內容可以在 PPT 中直接編輯。

#### 雙硬門檻

`結構可編輯` 和 `視覺還原` 是同等硬門檻，不是二選一。

**可編輯信息層門檻：**
- 主標題、副標題、正文、關鍵數字、圖表標籤、來源、頁碼、SO WHAT 和簡單圖表必須使用 PowerPoint 原生對象
- 除非在 manifest 中登記了明確且合規的非文字複雜視覺例外

**視覺語義高保真門檻：**
- 頁面表面系統、色彩層級、主圖表語義、曲線幅度、面板邏輯、底色系統、視覺重心必須忠實藍圖
- 不得以「可編輯」為理由把藍圖關鍵視覺表達簡化、替換或降級

#### 還原規則

| 區域 | 預設處理方式 | 說明 |
|------|--------------|------|
| 標題、副標題、正文、關鍵數字、頁腳、SO WHAT | 原生文本框 | 必須可編輯 |
| 折線圖、柱狀圖、坐標軸、標籤、對比條 | 原生形狀/圖表 | 必須原生重建 |
| 照片、官方 Logo、產品截圖、複雜插畫、3D、玻璃擬態 | 保留圖片 | 原生重建會明顯降質時才允許 |
| 大面積或整頁藍圖截圖 | 禁止 | 藍圖是參考，不是交付背景 |
| 簡單線條、分隔線、基礎幾何框、輕量標籤 | 原生形狀 | 必須可編輯 |
| 品牌 Logo、人物、商品圖、官方圖標 | 保留圖片 | 優先裁切原圖，不要手繪偽造 |

### 逐頁執行與驗收門

**進入第三階段時必須向用戶說明：**

> 接下來不是一次性生成完整 PPT，而是逐頁製作、逐頁驗收。
> 這樣做是為了避免 AI 在批量生成時注意力分散，導致信息密度下降、曲線/圖標/文字位置漂移、背景表面系統不一致和視覺語義丟失。
> 每頁確認通過後才進入下一頁；全部頁面通過後，再用已通過的单頁 PPTX 合併成完整 deck，並進行合併後回歸驗證。

#### 逐頁執行流程

每頁必須按順序執行：

1. 只讀取當前頁藍圖
2. 輸出當前頁 `blueprint_reconstruction_plan`
3. 完成當前頁 `complex_visual_scan`
4. 判斷圖片、SVG、custom geometry、複雜視覺資產准入
5. 判斷是否觸發精確曲線、像素邊界追蹤、表格密度、位置錨點、字號和溢出門
6. 只生成當前頁單頁 PPTX
7. 導出當前頁渲染圖
8. 生成當前頁 blueprint vs render side-by-side 對照圖
9. 對標題區、主圖表區、流程/圖標區、SO WHAT、頁腳等關鍵區域做局部對照
10. 填寫當前頁 manifest 與 visual QA evidence
11. 修復當前頁直到通過
12. 用戶確認當前頁後，才允許進入下一頁

**當前頁未通過前，不得製作下一頁。**

### 最終合併門

完整 PPTX 必須由已經逐頁驗收通過的单頁 PPTX 合併得到。

合併階段：
- 不得重新運行頁面生成腳本重建頁面
- 不得重新排版、重新繪製圖表、重新套用背景
- 不得將单頁渲染圖作為整頁背景
- 只能導入已驗收通過的单頁 PPTX 頁面
- 合併後必須導出 PNG 做回歸驗證

### 圖片資產准入表

制作每頁 PPTX 前必須先建立圖片資產准入表；沒有准入表不得開始生成該頁。

| 區域 | 預設是否允許圖片 | 判定 |
|------|------------------|------|
| 標題、副標題、正文、關鍵數字、頁腳、頁碼、SO WHAT | 否 | 主要信息層，必須可編輯 |
| 折線圖、柱狀圖、坐標軸、標籤、對比條、簡單流程箭頭 | 否 | 簡單圖表/基礎圖形，必須原生重建 |
| 照片、官方 Logo、產品 UI、複雜插畫、複雜紋理、3D | 可 | 原生重建會明顯降質時才允許 |
| 大面積或整頁藍圖截圖 | 否 | 藍圖是參考，不是交付背景 |

## 門禁機制

CyberPPT 內置 14 層門禁，防止「文件生成了，但證據、密度、可編輯性或視覺還原不合格」。

| # | 門禁 | 檢查什麼 | 失敗後處理 |
|---|------|----------|------------|
| 1 | Reference Gate | 每個階段開始前是否讀取對應 reference 文件 | 未讀取不得進入階段 |
| 2 | Evidence Gate | 所有事實、數字、判斷、建議是否可追溯到源材料 | 缺證據必須標記缺口或返工 |
| 3 | Storyline Gate | 是否完成 2-3 條故事線腦暴、比較和 SCR 收敛 | 不能只交單版大綱 |
| 4 | Density Gate | 每頁是否有信息密度、組件清單、圖表計劃和 SO WHAT | 低密度頁面必須補充或重排 |
| 5 | Style Gate | 是否展示 8 張獨立 16:9 風格樣張，並鎖定選定風格 | 不能只給文字風格說明 |
| 6 | Blueprint Gate | 是否為全部頁面生成逐頁 ImageGen 藍圖 | 藍圖未確認不得進入 PPTX |
| 7 | Asset Admission Gate | 每頁圖片資產是否有來源、必要性和可編輯性影響說明 | 無必要性的圖片必須改為原生重建 |
| 8 | Editable Layer Gate | 主標題、正文、關鍵數字、圖表標籤、頁腳、SO WHAT 是否可編輯 | 主要信息圖片化即失敗 |
| 9 | Visual Semantics Gate | 圖表語義、曲線、面板系統、底色、層級和視覺重心是否忠實藍圖 | 不能用「可編輯」解釋視覺降級 |
| 10 | Curve Trace Gate | 流線、弧線、異形邊界、Ribbon、桑基圖等是否精確追蹤 | 粗略矩形、少點折線或默認曲線失敗 |
| 11 | Spatial Registration Gate | 圖標、節點、標籤、箭頭、曲線是否按錨點對齊 | 沒重疊不代表位置合格 |
| 12 | Container Overflow Gate | 文字是否越過卡片、單元格、結論條、SO WHAT 或圖表區 | 容器內溢出即失敗 |
| 13 | Typography Gate | 字號是否符合固定 C0/T1-T14 層級 | 不得用無限縮字解決密度 |
| 14 | Strict QA Gate | `validate_cyberppt.py --strict` 是否通過 manifest 和 visual QA 檢查 | 出現 errors 必須返工 |

## 交付物

最終確認時必須提供：

1. **PPTX 文件** — 逐頁驗收通過的完整演示文稿
2. **全頁渲染圖** — 每頁的 PNG 渲染輸出
3. **`slide_manifest.json`** — 每頁的結構化描述（文本對象、原生組件、圖片資產、QA 預期）
4. **`visual_qa_gate.json`** — 雙硬門檻驗收結果（`editable_information_layer_pass` + `visual_semantics_preserved`）
5. **`validate_pptx.py --strict` 報告** — JSON 格式的 14 層門禁檢查結果

**任一關鍵門禁失敗，不得交付確認。**

## QA 驗證命令

```bash
# 嚴格模式 QA 檢查（必須包含 --manifest、--visual-qa 和 --strict）
python3 skills/ppt-master/scripts/validate_cyberppt.py \
  path/to/deck.pptx \
  --manifest path/to/slide_manifest.json \
  --visual-qa path/to/visual_qa.json \
  --strict \
  --json-out path/to/report.json
```

**strict 模式下報告出現 `errors` 即失敗，必須返工。**

## 與 PPT-Master 主流程的集成

### 何時使用此工作流

當用戶滿足以下任一條件時，啟動此工作流：

- 明確要求「諮詢風格」「MBB 級別」「證據鏈」「SCR 論證」「高密度」
- 提供董事會材料、高管匯報、戰略決策報告等場景
- 要求「嚴格 QA」「雙硬門檻」「14 層門禁」
- 要求「逐頁驗收」「混合還原」「可編輯 + 視覺保真」

### 與主流程的差異

| 特性 | 主流程 (SKILL.md) | 諮詢流程 (此工作流) |
|------|-------------------|---------------------|
| 證據分析 | 可選 | 強制 MBB 標準 |
| 故事線 | 單版大綱 | 2-3 條腦暴 + SCR 收敛 |
| 視覺風格 | 模板/品牌/自由選擇 | 8 種固定樣片確認 |
| 藍圖 | 可選 ImageGen 參考 | 強制逐頁藍圖 |
| 還原策略 | 預設原生重建 | 混合還原（複雜視覺 + 可編輯） |
| QA 門禁 | svg_quality_checker.py | 14 層門禁 + validate_cyberppt.py |
| 逐頁驗收 | 批量生成 | 逐頁執行 + 逐頁確認 |

### 流程切換規則

1. 用戶在項目創建時或 Step 1 前指定使用諮詢模式
2. 系統載入本工作流替代標準 Strategist 八步確認
3. 階段 2 的視覺風格確認使用 8 種固定樣片而非模板庫
